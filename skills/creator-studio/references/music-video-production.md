# Existing-song character music videos

Do your own current research (code, checkpoint and dependency licenses; real samples) before selecting models or claiming an installed singing capability. The user's canonical song/creatures can live in another owning project; record exact source URLs/paths and hashes instead of silently substituting another generated clip.

## Route and truth boundaries

- Preserve the approved song as one immutable master and one timebase. Skip narration/TTS/new-song generation. Model-generated audio must be muted; mux the master once, without amixing duplicated vocals or using shortest to hide a short picture track.
- Distinguish beat-synced montage, image-driven mouth movement, audio-conditioned performance and phoneme-accurate lip sync. A video generator plus soundtrack mux is a performance montage, not verified lip sync.
- If the user selects an existing successful video, use it as the actual visual base. Do not let a parallel research or revision effort replace that choice. Full song requires enough distinct footage; a ten-second loop is not a full generated performance.
- Inspect the user's exact linked conversation/clip before fixing identity. Preserve earlier versions. Compare against both approved creature and authorized original portrait; preserve other characters and shot style. Do not overwrite browser drafts; coordinate concurrent generation before starting another paid request.

## Audio-driven OSS selection

- MultiTalk is a practical documented cartoon/singing 480p baseline; LongCat Avatar1.5 is a newer feature-rich challenger; InfiniteTalk is a redubbing/continuation alternative. Revalidate exact current code and checkpoint licenses, dependencies and GPU fit rather than treating this shortlist as proven output quality.
- Check actual speaker slots: inspected releases bind one or two active streams. Silent-background boxes are not person3. Use solos/duets or separate-pass compositing until three-way control is actually proven.
- A vocals/instrumental separator does not separate singers. Prefer original singer stems; otherwise explicitly reviewed time-gated lanes for sequential turns. Diarization is not overlapping waveform separation. Keep all lanes sample-aligned with silence outside active intervals.
- LongCat's official driver loads Kim_Vocal_2 even when supplying already-separated audio; inspect/change that path only through a reviewed adapter if the checkpoint rights/access cannot be cleared. Apache/MIT wrapper licenses do not relicense every weight. Do not default to Wav2Lip/Sonic noncommercial releases for a reusable commercial pipeline.
- Read actual mask coordinates in pinned implementation; YXYX versus XYXY differs across wrappers. Verify one active singer at a time, then overlap, before full-song spend.

## Production and acceptance

1. Stage under `productions/<name>/`; preserve full-song master, character/reference hashes, approved style frame, provider prompts/receipts and an absolute shot timeline.
2. Read the decoded master sample count/rate and build an absolute shot-duration ledger before generation. Allocate the approved existing clip first, then enough distinct source footage for the remaining windows. Check the provider's current usage banner before assigning work; when an authorized alternative is needed, carry the selected clip's actual style frame across providers rather than regenerating the characters from prose. Reuse installed HyperFrames music analysis for beat proposals, not ground-truth song sections or lyric/phoneme timing.
3. Enforce both create-request pacing and a separate in-flight-job ceiling. A provider can accept one create per minute yet reject another because earlier renders still occupy all concurrent slots. Persist each remote job ID before polling and release its slot only after a terminal state. Keep per-shot prompts, receipts and failure evidence; an explicit HTTP429 concurrency rejection with no job ID is distinct from an ambiguous network timeout. Review that response before resubmitting after capacity frees; do not blindly retry paid POSTs or call a queued/rendering job usable footage.
4. Check every source actually covers its required picture interval using the video stream duration/frame count, not only container duration; an AAC tail can make the container longer than its pictures. Use available unused source tails before requesting more paid footage. Normalize picture-only frame rate/resolution without changing playback speed, assemble the complete song duration and only then mux the master once. Allow a documented final-frame rounding tolerance, not a missing song tail. If a render is blocked, retain its terminal error, omit that output and explicitly revise the edit; a short original audio-reactive graphic cutaway can cover an editorial break, but must not be reported as a successful character-performance generation.
5. Run full decode/ffprobe and inspect exported frames for every closeup/cut/end; verify identity, speaker binding, held vowels/plosives/rests if claiming singing sync. Human-face sync metrics are not a definitive chibi score.
6. Check actual FFmpeg filters before enabling burned subtitles; a build without libass can fail an existing caption test. Do not silently skip baseline failures or imply a valid codec proves quality.
7. GPU jobs are a separate CUDA substrate from Azure OpenAI deployments. Query exact service/environment quota and regional profile support; host memory is not GPU VRAM, and quota is not physical allocation. Use bounded scale-to-zero jobs and actual CUDA/peak-memory evidence before recommending song render costs.

## Final-song assembly and delivery

1. Gate assembly on every selected source file, its video coverage and its provenance. Persist a timeline manifest with source hashes, actual intervals, intended role and review result; labels such as a prop-comedy shot describe intent until the prop is visibly verified.
2. Normalize each source as **video only**, resetting timestamps and matching canvas, pixel format and frame rate. Concatenate those normalized files, then mux the untouched lossless song master exactly once. Do not slow mouth footage to fill missing coverage or add `-shortest` to hide a short picture track.
3. Probe the actual export with `ffprobe -v error -show_entries format=duration,size:stream=codec_name,codec_type,width,height,r_frame_rate,duration -of json <final.mp4>` and run `ffmpeg -v error -i <final.mp4> -f null -`. Require the full soundtrack, exactly one intended audio stream and picture coverage within a documented output-frame tolerance.
4. Check soundtrack continuity independently of codec success: decode master and export with identical settings, e.g. `ffmpeg -v error -i <input> -map 0:a:0 -ac 1 -ar 16000 -f f32le -`. Compare decoded sample counts, waveform correlation and RMS ratio using NumPy. Record actual metrics and tolerances chosen for the codec; AAC is lossy, so do not claim byte identity. This detects wrong/truncated/duplicated soundtrack content, not lip sync or complete listening quality.
5. Inspect frames from the **final MP4**, not just source clips: each character close-up, both sides of important cuts, any graphic insert, and a frame near the true end. Keep sampled visual approval distinct from an exhaustive motion review and exact singing synchronization.
6. Only after these checks, mark the canonical output ready, reveal that file in Finder, and provide its exact path/native attachment. `open -R <final.mp4>` reveals a file; opening its parent directory does not prove a final exists. For playback use `open -a 'QuickTime Player' <final.mp4>` and verify the exact document/window. If a focus/activation method stalls, use the working desktop focus action and read back the matching title instead of repeatedly issuing unverified launch commands.

## Sora2 API lessons

Use the current documented `/openai/v1/videos` multipart API for the deployed model, not legacy Sora1 job schema snippets that can coexist on the same docs page. Fields include deployment name, size, seconds and input_reference with exact matching image dimensions. Verify account keyless auth and resolve Entra token only in process (the tested video documentation uses ai.azure.com scope). Read back deployment, then exercise the actual image-reference job; ARM Succeeded alone is not inference proof. Sora visual references do not provide recorded-song audio conditioning. Keep catalog deprecation dates in project evidence and do not make a short-lived preview a durable default.
